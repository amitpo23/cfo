**נכתב:** 2026-07-30 · **מבוסס על בדיקה חיה של סביבת הפרוד ושל הקוד** (לא הערכה)

## מצב נוכחי — מה נבדק בפועל

| רכיב | מצב | ראיה |
|---|---|---|
| `WHATSAPP_PHONE_NUMBER_ID` / `ACCESS_TOKEN` / `VERIFY_TOKEN` / `APP_SECRET` | ✅ **מוגדרים בפרוד** (לפני 4 ימים) | `vercel env ls production` |
| `ANTHROPIC_API_KEY` | ✅ מוגדר | שם |
| ראוט ה-webhook חי | ✅ `GET /api/whatsapp/webhook` → **403** (דוחה בלי חתימה — התנהגות נכונה, הראוט קיים ופרוס) | curl |
| בריאות האפליקציה | ✅ `/api/health` → 200 | curl |
| **`SMTP_HOST/PORT/USER/PASSWORD/FROM`** | ❌ **לא מוגדר אף אחד** | `vercel env ls production` — אין אף משתנה SMTP |
| **`TELEGRAM_BOT_TOKEN`** | ❌ **לא מוגדר** | שם |
| observability (טוקנים/עלות/לוג כלים/מסך אדמין) | ❌ לא קיים | חקירת קוד; `response.usage` נזרק, אפס `logger` בנתיב השיחה |
| דחיפה יזומה לוואטסאפ | ❌ `channel_notifier.py:67,93,109` מקודד טלגרם | קוד |

**המסקנה:** ‏WhatsApp מוגדר מצד Meta, אבל **אף משתמש לא יוכל להתחבר** — כי החיבור עובר אך ורק דרך קוד שנשלח במייל, ו-SMTP לא מוגדר. זה החוסם היחיד והמיידי.

## שרשרת הקליטה — למה SMTP חוסם הכול

1. משתמש שולח הודעה למספר העסקי → הבוט לא מזהה אותו (`ChannelIdentity` ריק).
2. הבוט מבקש **כתובת מייל רשומה ברצף** — `whatsapp_webhook.py:74-77`.
3. משתמש שולח מייל → `start_email_verification` מייצר קוד בן 6 ספרות ומנסה לשלוח במייל.
4. **`send_email_smtp` מחזיר `False`** כי `smtp_host`/`smtp_from` ריקים ([email_sender.py:36-38](src/cfo/services/email_sender.py:36)) → `channel_link_service.py:334-343` שורף את הקוד ומחזיר `status: "email_unavailable"`.
5. **אין מסלול חלופי בוואטסאפ.** (קוד-הקישור מהאפליקציה קיים — אבל הוא טלגרם-בלבד.)

# תוכנית הביצוע

## שלב 1 — SMTP (חוסם; ~10 דקות; הבעלים)
נדרשים חמישה משתנים ב-Vercel Production. שני מסלולים:

**מסלול א' — Gmail (הכי מהיר).** דורש 2FA פעיל בחשבון, ואז **App Password** (16 תווים) מ-`myaccount.google.com/apppasswords`:
```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=amitporat1981@gmail.com
SMTP_PASSWORD=<app-password, לא סיסמת החשבון>
SMTP_FROM=amitporat1981@gmail.com
```
מגבלה: ~500 מיילים ליום, והשולח יופיע כ-Gmail אישי.

**מסלול ב' — Resend / SendGrid (מקצועי).** דומיין משלך, deliverability טוב יותר, מכסה חינם ~3,000/חודש. דורש אימות דומיין (רשומות DNS) — 20–30 דקות.

**המלצה:** להתחיל ב-Gmail כדי לפתוח את החסימה היום; לעבור לספק ייעודי כשמושקו נפתח ללקוחות אמיתיים.

**אימות אחרי ההגדרה:** לשלוח הודעה למספר העסקי → לשלוח את המייל → לוודא שהקוד מגיע.

## שלב 2 — אימות המסלול מקצה לקצה (הבעלים; ~5 דקות)
1. לוודא ב-Meta ← WhatsApp ← Configuration: Callback URL = `https://cfo-2.vercel.app/api/whatsapp/webhook`, Verify Token תואם, ו-**Subscribe ל-`messages`**.
2. לוודא שהמספר שלך ברשימת ה-recipients (עד 5 במספר הבדיקה).
3. הרצת סקריפט האימות — **הבעלים בלבד** (קריאות רשת חיות, חסום לסוכנים):
```bash
python scripts/check_whatsapp_setup.py --send-to 972<המספר-שלך>
```
4. שיחת בדיקה: לשלוח "שלום", לעבור אימות מייל, ולשאול שאלה עסקית.

## שלב 3 — observability (Codex, בביצוע כעת)
נשלח ל-Codex (gpt-5.6-sol) ורץ ברקע. מה שנבנה:
- **מדידת טוקנים ועלות** — קריאת `response.usage` שנזרקת היום, טבלת שימוש, תמחור פר-מודל בקונפיג, `cost=NULL` למודל לא מוכר (honest-null). כולל קריאות הביניים בלולאת הכלים.
- **לוג קריאות כלים** — כל ~40 הכלים, עם סיווג יעד (`sumit` / `open_finance` / `rezef_db` / `local`), הצלחה/כשל, משך, וארגומנטים מחוטאים מערכים רגישים.
- **ראוטים לאדמין** תחת `/api/admin/moshko/` — `conversations`, `tool-calls`, `usage` — SUPER_ADMIN בלבד, עם טסטי הרשאות ואי-דליפה בין ארגונים.
- **מסך frontend** בסגנון `AdminClientsDashboard`.
- **דחיפה יזומה לוואטסאפ** — הכללת `channel_notifier` לשני ה-providers, כולל טיפול כן בחלון 24 השעות של Meta.

## החלטה פתוחה — טלגרם
`TELEGRAM_BOT_TOKEN` לא מוגדר בפרוד, כלומר **טלגרם לא פעיל כלל** למרות שהקוד מלא ומוקשח. לטלגרם יש יתרון: קוד-קישור מהאפליקציה (בלי תלות ב-SMTP), ואין מגבלת חלון-24-שעות לדחיפות. שווה לשקול להפעיל אותו במקביל — טוקן מ-BotFather זה 2 דקות.
