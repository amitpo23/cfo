# Runbook — הפעלת מושקו מקצה לקצה

מדריך ההפעלה המלא: מהאימות מול SUMIT ו-Open Finance, דרך גישה לידע וליכולות,
ועד שיחה מלאה בוואטסאפ. מיועד ל**בעלים** — כל שלב כאן דורש סוד, מספר טלפון או
גישה לפרוד, ולכן אינו מבוצע ע"י סוכן.

> **מה מושקו**: זהות אחת עם שלושה כובעים — מנהלת חשבונות, מנהל כספים, רואה
> חשבון. עונה רק מנתוני המערכת, זוכר העדפות, ולא מבצע שום פעולה בלתי-הפיכה
> בלי אישור מפורש שמציג את הארגומנטים בפועל.

## שלב 1 — אימות מול SUMIT

**ההקשר החשוב**: ה-API של SUMIT **אינו חושף** את רשימת המשתמשים, התפקידים או
המספרים המורשים (אומת מול כל 84 ה-endpoints — המסך `companies/roles` הוא UI
בלבד). לכן רצף **אינה נשענת** על ההרשאות של SUMIT לזיהוי, אלא על טבלת
המשתמשים שלה עצמה. מ-SUMIT נדרש רק חיבור נתונים.

לכל ארגון:
1. בפורטל SUMIT: הגדרות ← ‏API ← הפק **API Key**, ורשום את ה-**CompanyID**
   (המספר שמופיע ב-URL: `companyid=...`).
2. ברצף: הזן אותם לכספת המוצפנת של אותו ארגון (`IntegrationConnection` עם
   `source="sumit"`). משתני סביבה מותרים **רק** ל-org 1.
3. אימות: שאל את מושקו "מה מצב הסנכרון?" — הוא יפעיל את `get_engine_status`.

## שלב 2 — אימות מול Open Finance

1. השלם את מסע ההסכמה (consent) לכל בנק/כרטיס של העסק. החשבונות מגיעים
   ממילא משויכים לארגון שנתן את ההסכמה.
2. המתן לסנכרון היומי (‏02:00 UTC) — או הפעל ידנית פעם אחת.
3. **התאמת הבעלות אוטומטית**: המערכת משווה שלושה מזהים — ח.פ מהבנק
   (`ownerInfo.nationalId`), `tax_id` של הארגון, ו-`CorporateNumber` מ-SUMIT.
   מתלכדים ← אין מה לעשות.
4. **רק אם לא מתלכדים** — הפריט נכנס לתור ההכרעה שלך:
   `GET /api/admin/moshko/ownership-review` (סופר-אדמין בלבד). כל פריט מציג את
   שלושת המקורות זה מול זה. ההכרעה נרשמת ב-`AuditLog`.

> העמודות `owner_national_id` / `owner_name` מתמלאות **בסנכרון הבא ללא קריאת
> API נוספת**. אין צורך לרענן ידנית ואין עלות.

## שלב 5 — תנאי מקדים חובה: SMTP

**אין להפעיל WhatsApp לפני שהמייל עובד.** החיבור לערוץ מתבצע רק כך: העוסק
שולח את כתובת המייל הרשומה שלו בוואטסאפ, מקבל קוד בן 6 ספרות במייל ומחזיר
אותו בוואטסאפ. אין בוואטסאפ מסלול חלופי; קוד הקישור מהאפליקציה הוא
**ל-Telegram בלבד**. בלי SMTP, המערכת שורפת את הקוד שלא נשלח ומחזירה
`email_unavailable` — ולכן אף משתמש לא יוכל להתחבר.

הגדר ב-Vercel (Production) את **כל חמשת המשתנים**:

| משתנה | ערך ב-Gmail |
| --- | --- |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `587` |
| `SMTP_USER` | כתובת חשבון Gmail השולח |
| `SMTP_PASSWORD` | App Password בן 16 תווים — **לא** סיסמת חשבון Google |
| `SMTP_FROM` | כתובת השולח, בדרך כלל זהה ל-`SMTP_USER` |

ב-Gmail יש להפעיל אימות דו-שלבי (2FA), להפיק App Password ב-
`myaccount.google.com/apppasswords`, ולהדביק את 16 התווים ב-
`SMTP_PASSWORD` **בלי רווחים**.

> ⚠️ **משתני סביבה חדשים או מעודכנים ב-Vercel נכנסים לתוקף רק אחרי
> Redeploy.** בצע Redeploy לפני בדיקת החיבור בוואטסאפ.

בחר אחד משני מסלולי המספר — 5א לבדיקה מהירה או 5ב לפרודקשן — ולאחר הגדרת
ה-webhook המשך בכל מקרה לאימות החובה בשלב 5ג.

## שלב 5א — PoC מהיר: מספר הבדיקה של Meta ⭐

**זה המסלול להתחלה.** ‏Meta נותנת מספר בדיקה **חינם ומיידי, בלי אימות עסקי** —
אפשר אפילו ליצור Test Business Account. הקוד שלנו עובד איתו כמו שהוא.

1. `developers.facebook.com` ← **Create App** ← סוג **Business**.
2. במסך המוצרים ← **WhatsApp** ← **Set up**. נוצרים אוטומטית מספר בדיקה
   ו-Test Business Account.
3. במסך **API Setup**:
   - העתק את **Phone number ID** (⚠️ ה-ID, לא המספר עצמו — זו הטעות הנפוצה).
   - העתק את ה-**Temporary access token**. הוא קשור לסשן הפייסבוק של המשתמש
     ותקף **24 שעות בלבד** — מספיק לבדיקה מהירה, לא לפרודקשן. לטווח ארוך
     הפק טוקן System User לפי שלב 5ב.
   - תחת **To** ← **Manage phone number list** ← הוסף את המספרים שיבדקו.
     **עד 5 נמענים** — זו המגבלה היחידה שתרגיש.
4. **App Secret**: Settings ← Basic ← **Show**.
5. **Verify token**: מחרוזת שאתה בוחר — `openssl rand -hex 16`.
6. הזן את ארבעת הערכים ל-Vercel (Production) ואמת:

```bash
python scripts/check_whatsapp_setup.py --send-to 972501234567
```

הסקריפט בודק שהערכים קיימים, שה-token באמת מורשה על המספר, ושחישוב חתימת
ה-webhook תקין — ומסביר מה לתקן בכל כשל. ⚠️ **קריאות רשת חיות — הרצה ידנית
של הבעלים בלבד** (חסום לסוכנים ב-`AGENTS.md`).

> ⚠️ **הסקריפט אינו בודק איזו אפליקציה רשומה ברמת ה-WABA.** גם אם הוא עובר,
> חובה לבצע ידנית את בדיקת `subscribed_apps` בשלב 5ג.

7. **Webhook**: WhatsApp ← Configuration ← Callback URL
   `https://cfo-2.vercel.app/api/whatsapp/webhook`, ה-Verify Token שלך,
   ו-Subscribe ל-**messages**.

**מגבלות שכדאי לדעת מראש**: עד 5 נמענים, והמספר מוקצה ע"י Meta ואינו קבוע —
לא ניתן למתג אותו כ"המספר של מושקו" לצמיתות. המעבר למספר קבוע אחרי אימות
עסקי הוא **החלפת ארבעה ערכים, אפס שינוי קוד**.

## שלב 5ב — מספר פרודקשיין קבוע

1. **חשבון**: צור/ודא Meta Business Account מאומת.
2. **מספר**: הוסף מספר ייעודי ב-WhatsApp Manager. חייב להיות מספר ש**אינו רשום
   כיום בוואטסאפ רגיל** — אם כן, מחק אותו משם קודם.

3. **טוקן קבוע לפרודקשן — System User**: ה-Temporary access token ממסך API
   Setup פג אחרי 24 שעות. לפרודקשן הפק טוקן של משתמש מערכת לפי הרצף הבא:
   1. היכנס ל-`business.facebook.com` ← **Business Settings** ← **משתמשי
      מערכת**, וצור משתמש מערכת בתפקיד **Admin**.
   2. תחת הקצאת נכסים, הקצה למשתמש המערכת **שני נכסים נפרדים — ושניהם
      חובה**:
      - חשבון ה-WhatsApp Business.
      - **האפליקציה עצמה**.

      בלי הקצאת האפליקציה, אשף הטוקן מציג "אין הרשאות זמינות" ולא מאפשר
      להמשיך.
   3. אחרי הקצאת הנכסים, **רענן את הדף** אם האשף עדיין אינו רואה אותם.
   4. פתח את אשף הפקת האסימון ובחר:
      - את האפליקציה.
      - תפוגה **"אף פעם"**.
      - הרשאות `whatsapp_business_messaging` ו-
        `whatsapp_business_management`. אם הרשימה נראית ריקה, **הקלד
        `whatsapp` בשדה החיפוש** כדי להציג אותן.
   5. השלם אימות חשבון ב-SMS אם Meta דורשת זאת.
   6. ⚠️ **הטוקן מוצג פעם אחת בלבד.** העתק אותו מיד; ניווט באותו טאב סוגר
      את הדיאלוג ומאבד את הטוקן. במקרה כזה יש להפיק טוקן חדש.
4. **סודות** ל-Vercel (Production):

   | משתנה | מקור |
   | --- | --- |
   | `WHATSAPP_PHONE_NUMBER_ID` | ‏WhatsApp Manager |
   | `WHATSAPP_ACCESS_TOKEN` | טוקן קבוע של האפליקציה |
   | `WHATSAPP_VERIFY_TOKEN` | מחרוזת שאתה בוחר (`openssl rand -hex 16`) |
   | `WHATSAPP_APP_SECRET` | ‏Meta App ← Settings ← Basic |

   אחרי הזנת הסודות בצע **Redeploy**, ורק אז המשך לבדיקה.
5. **Webhook**: ב-Meta App ← WhatsApp ← Configuration:
   - Callback URL: `https://cfo-2.vercel.app/api/whatsapp/webhook`
   - Verify Token: הערך מ-`WHATSAPP_VERIFY_TOKEN`
   - Subscribe ל-`messages`
6. **תבניות** (רק להתרעות יזומות מחוץ לחלון 24 שעות): צור תבניות `utility`
   ואשר אותן ב-Meta. שיחה שהעוסק פתח — טקסט חופשי מותר, בלי תבנית.

אם הודעה נכנסת ומעובדת, אבל בלוגים מציגים
`POST https://graph.facebook.com/v21.0/{phone_number_id}/messages "HTTP/1.1 401 Unauthorized"`,
הבוט ניסה לענות והטוקן נדחה. בטוקן זמני, הפק חדש לבדיקה; בפרודקשן, ודא
שהוגדר טוקן System User קבוע ושהפריסה בוצעה מחדש.

> **תקציב**: הודעות שירות בתוך חלון 24 שעות חינם **עד 1.10.2026**; מאותו
> תאריך Meta מחייבת גם עליהן.

## שלב 5ג — אימות חובה: רישום ה-webhook ברמת ה-WABA

ל-WhatsApp Cloud API יש שתי שכבות רישום נפרדות, ושתיהן חייבות להיות תקינות:

1. **רמת האפליקציה** — Callback URL, ‏Verify Token ו-Subscribe ל-`messages`
   בדשבורד. זהו ה-webhook שהוגדר בשלב 5א או 5ב.
2. **רמת ה-WABA** — האפליקציה שרשומה לקבל את ההודעות של חשבון ה-WhatsApp
   Business עצמו.

אמת את השכבה השנייה מיד אחרי הגדרת ה-webhook:

1. פתח Graph API Explorer ובחר בו את **האפליקציה שלך** ב-Meta App.
2. הרץ `GET /{WABA_ID}/subscribed_apps`. לדוגמה, עם ה-WABA של מושקו:
   `GET /1066396829218336/subscribed_apps`.
3. ודא שהשם שחוזר הוא **האפליקציה שלך**. אם חוזרת האפליקציה הפנימית של Meta
   **"WA DevX Webhook Events 1P App"** (`id: 2202427980234937`), היא נרשמה
   אוטומטית מכלי הבדיקה בדשבורד ובולעת את ההודעות הנכנסות.
4. לתיקון, הרץ באותו Explorer ובאותה אפליקציה:
   `POST /{WABA_ID}/subscribed_apps`. התוצאה הצפויה היא
   `{"success": true}`.
5. הרץ שוב את בקשת ה-GET וודא שהאפליקציה שלך היא הרשומה.

> **התסמין המטעה**: הודעות המשתמש מקבלות ✓✓ וכפתור **Test** בדשבורד מחזיר
> "Successfully tested", אבל אין בלוגי שרת שום בקשה. כפתור Test פונה ישירות
> ל-Callback URL ועוקף את ניתוב ה-WABA; לכן הצלחתו **אינה** מוכיחה שהודעות
> אמיתיות יגיעו לשרת.

## שלב 9 — שאלות ובקשות (מה אפשר לבקש)

**שאלות**: "מה התזרים שלי?" · "מתי צפוי מינוס בחשבון?" · "מי לא שילם לי?" ·
"מה מצב המע"מ?" · "האם קלטת את ההוצאות של החודש?" · "מה חסר לי לדיווח?" ·
"כמה מס אני צריך לשלם?" (יגיע **תמיד** עם הסתייגות — האומדן גס) ·
"מה כדאי לשפר בעסק?" (יענה ממספרים אמיתיים, לא מעצות כלליות).

**בקשות פעולה**: "תייק את ההוצאה הזאת" · "שלח לבנק את הרווח וההפסד של יוני" ·
"תוציא חשבונית ללקוח X" · "רשום שדיברתי עם הלקוח על החוב".

**דיווח מע"מ**: "תאשר לי את הדיווח של יוני" — מושקו יריץ אימות משולש, יציג את
המספרים, וירשום את אישורך. ⚠️ **רצף אינה משדרת לרשות המסים** — השידור בפועל
נעשה בממשק SUMIT. אם האימות נכשל, מושקו **חוסם** ולא נותן לאשר.

חריגת מסגרת, פערי מסמכים ותובנות דחופות נדחפות אליך. שעות שקט **22:00–07:00**
שרק התרעה קריטית חוצה. אפשר לכבות לכל מכשיר בנפרד (`push_enabled`).

## מה לבדוק אחרי ההפעלה

| בדיקה | ציפייה |
| --- | --- |
| `GET /{WABA_ID}/subscribed_apps` | האפליקציה שלך רשומה, לא `WA DevX Webhook Events 1P App` |
| הודעה ממספר לא מקושר | הסבר חיבור בלבד. **אפס עלות LLM** |
| מייל רשום לאחר שליחת הכתובת | קוד בן 6 ספרות מתקבל במייל; אין `email_unavailable` |
| מייל שאינו רשום | אותה תשובה בדיוק כמו מייל רשום, ובאותו זמן |
| קוד ממכשיר אחר | נדחה |
| "מה התזרים שלי?" | מספרים מהמערכת, לא מהמודל |
| "כמה מס אשלם?" | **חייב** להופיע עם הסתייגות |
| צילום קבלה | ספק/סכום/מע"מ — ובקשת אישור לתיוק |
| בקשת שליחת דוח | כרטיס אישור שמציג את **כתובת הנמען המלאה** |
| "מה מצב המנוע?" | `kb_files_available` > 0 |
| שאלה על דין/נוהל | שימוש ב-`kb_lookup`, לא ניחוש מהזיכרון |

## כיבוי חירום

- וואטסאפ: הסר את ה-Webhook ב-Meta App, או מחק את `WHATSAPP_ACCESS_TOKEN`.
- טלגרם: `POST https://api.telegram.org/bot<TOKEN>/deleteWebhook`.
- משתמש בודד: סמן `revoked_at` ב-`ChannelIdentity` שלו — זהות מבוטלת מתנהגת
  בדיוק כמו זהות שאינה קיימת.
- קליטת קבלות: `CHAT_RECEIPT_INTAKE_ENABLED=false`.
- התרעות: `push_enabled=false` על הזהות.
