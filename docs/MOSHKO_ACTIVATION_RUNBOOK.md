# Runbook — הפעלת מושקו מקצה לקצה

מדריך ההפעלה המלא: מהאימות מול SUMIT ו-Open Finance, דרך גישה לידע וליכולות,
ועד שיחה מלאה בוואטסאפ. מיועד ל**בעלים** — כל שלב כאן דורש סוד, מספר טלפון או
גישה לפרוד, ולכן אינו מבוצע ע"י סוכן.

> **מה מושקו**: זהות אחת עם שלושה כובעים — מנהלת חשבונות, מנהל כספים, רואה
> חשבון. עונה רק מנתוני המערכת, זוכר העדפות, ולא מבצע שום פעולה בלתי-הפיכה
> בלי אישור מפורש שמציג את הארגומנטים בפועל.

## שלב 0 — מיזוג ופריסה

1. מזג את PR #11 ל-`main`. הפריסה ל-Vercel אוטומטית.
2. הרץ את המיגרציות בפרוד לפי `docs/GATE0_DEPLOYMENT_RUNBOOK.md`.
   ‏`create_all` **לא** יוסיף את הטבלאות והעמודות החדשות.
3. ודא ראש יחיד: `python -m alembic heads`.

## שלב 1 — אימות מול SUMIT

**ההקשר החשוב**: ה-API של SUMIT **אינו חושף** את רשימת המשתמשים, התפקידים או
המספרים המורשים (אומת מול כל 84 ה-endpoints — המסך `companies/roles` הוא UI
בלבד). לכן רצף **אינה נשענת** על ההרשאות של SUMIT לזיהוי, אלא על טבלת
המשתמשים שלה עצמה. מ-SUMIT נדרש רק חיבור נתונים.

לכל ארגון:
1. בפורטל SUMIT: הגדרות ← ‏API ← הפק **API Key**, ורשום את ה-**CompanyID**
   (המספר שמופיע ב-URL: `companyid=...`).
2. ברצף: הזן אותם לכספת המוצפנת של אותו ארגון (`IntegrationConnection` עם
   `source="sumit"`). משתני סביבה מותרים **רק** ל-org 1.
3. אימות: שאל את מושקו "מה מצב הסנכרון?" — הוא יפעיל את `get_engine_status`.

## שלב 2 — אימות מול Open Finance

1. השלם את מסע ההסכמה (consent) לכל בנק/כרטיס של העסק. החשבונות מגיעים
   ממילא משויכים לארגון שנתן את ההסכמה.
2. המתן לסנכרון היומי (‏02:00 UTC) — או הפעל ידנית פעם אחת.
3. **התאמת הבעלות אוטומטית**: המערכת משווה שלושה מזהים — ח.פ מהבנק
   (`ownerInfo.nationalId`), `tax_id` של הארגון, ו-`CorporateNumber` מ-SUMIT.
   מתלכדים ← אין מה לעשות.
4. **רק אם לא מתלכדים** — הפריט נכנס לתור ההכרעה שלך:
   `GET /api/admin/moshko/ownership-review` (סופר-אדמין בלבד). כל פריט מציג את
   שלושת המקורות זה מול זה. ההכרעה נרשמת ב-`AuditLog`.

> העמודות `owner_national_id` / `owner_name` מתמלאות **בסנכרון הבא ללא קריאת
> API נוספת**. אין צורך לרענן ידנית ואין עלות.

## שלב 4 — גישה ליכולות SUMIT ו-Open Finance

אחרי שלבים 1–2, היכולות זמינות אוטומטית ככלים. **מה שמושקו יכול לקרוא**:
הוצאות וסטטוס תיוק, מוכנות PCN874 ומצב מע"מ, רווח והפסד מהספרים החיים, גיול

לספרים, רישום ניסיון גבייה, יצירת לינק תשלום, בקשת תשלום בנקאית, חיבור חשבון,

## שלב 5א — PoC מהיר: מספר הבדיקה של Meta ⭐

**זה המסלול להתחלה.** ‏Meta נותנת מספר בדיקה **חינם ומיידי, בלי אימות עסקי** —
אפשר אפילו ליצור Test Business Account. הקוד שלנו עובד איתו כמו שהוא.

1. `developers.facebook.com` ← **Create App** ← סוג **Business**.
2. במסך המוצרים ← **WhatsApp** ← **Set up**. נוצרים אוטומטית מספר בדיקה
   ו-Test Business Account.
3. במסך **API Setup**:
   - העתק את **Phone number ID** (⚠️ ה-ID, לא המספר עצמו — זו הטעות הנפוצה).
   - העתק את ה-**Temporary access token**. לטווח ארוך הפק Permanent token
     דרך System User.
   - תחת **To** ← **Manage phone number list** ← הוסף את המספרים שיבדקו.
     **עד 5 נמענים** — זו המגבלה היחידה שתרגיש.
4. **App Secret**: Settings ← Basic ← **Show**.
5. **Verify token**: מחרוזת שאתה בוחר — `openssl rand -hex 16`.
6. הזן את ארבעת הערכים ל-Vercel (Production) ואמת:

```bash
python scripts/check_whatsapp_setup.py --send-to 972501234567
```

הסקריפט בודק שהערכים קיימים, שה-token באמת מורשה על המספר, ושחישוב חתימת
ה-webhook תקין — ומסביר מה לתקן בכל כשל. ⚠️ **קריאות רשת חיות — הרצה ידנית
של הבעלים בלבד** (חסום לסוכנים ב-`AGENTS.md`).

7. **Webhook**: WhatsApp ← Configuration ← Callback URL
   `https://cfo-2.vercel.app/api/whatsapp/webhook`, ה-Verify Token שלך,
   ו-Subscribe ל-**messages**.

**מגבלות שכדאי לדעת מראש**: עד 5 נמענים, והמספר מוקצה ע"י Meta ואינו קבוע —
לא ניתן למתג אותו כ"המספר של מושקו" לצמיתות. המעבר למספר קבוע אחרי אימות
עסקי הוא **החלפת ארבעה ערכים, אפס שינוי קוד**.

## שלב 5ב — מספר פרודקשיין קבוע

1. **חשבון**: צור/ודא Meta Business Account מאומת.
2. **מספר**: הוסף מספר ייעודי ב-WhatsApp Manager. חייב להיות מספר ש**אינו רשום
   כיום בוואטסאפ רגיל** — אם כן, מחק אותו משם קודם.
3. **סודות** ל-Vercel (Production):

   | משתנה | מקור |
   | --- | --- |
   | `WHATSAPP_PHONE_NUMBER_ID` | ‏WhatsApp Manager |
   | `WHATSAPP_ACCESS_TOKEN` | טוקן קבוע של האפליקציה |
   | `WHATSAPP_VERIFY_TOKEN` | מחרוזת שאתה בוחר (`openssl rand -hex 16`) |
   | `WHATSAPP_APP_SECRET` | ‏Meta App ← Settings ← Basic |

4. **Webhook**: ב-Meta App ← WhatsApp ← Configuration:
   - Callback URL: `https://cfo-2.vercel.app/api/whatsapp/webhook`
   - Verify Token: הערך מ-`WHATSAPP_VERIFY_TOKEN`
   - Subscribe ל-`messages`
5. **תבניות** (רק להתרעות יזומות מחוץ לחלון 24 שעות): צור תבניות `utility`
   ואשר אותן ב-Meta. שיחה שהעוסק פתח — טקסט חופשי מותר, בלי תבנית.

> **תקציב**: הודעות שירות בתוך חלון 24 שעות חינם **עד 1.10.2026**; מאותו
> תאריך Meta מחייבת גם עליהן.

## שלב 6 — חיבור העוסק למושקו

1. העוסק שומר את מספר מושקו באנשי הקשר.
2. שולח הודעה כלשהי.
3. מושקו מבקש את המייל שלו **ברצף**.
4. נשלח קוד בן 6 ספרות **למייל הרשום** (לא ל-וואטסאפ) — אימות דו-גורמי בפועל.
5. העוסק מקליד את הקוד ← מקושר.

הקשחות: הקוד תקף 10 דקות, חד-פעמי, **ניתן למימוש רק מהמכשיר שביקש**; ‏3 בקשות
קוד לשעה; ‏5 ניחושים כושלים לשעה; והתשובה זהה בין כתובת רשומה ללא-רשומה, כולל
זמן התגובה. **לפני אימות — אפס גישה למידע, אפס קריאת LLM, אפס הורדת מדיה.**

## שלב 8 — שליחת חומר למושקו

שלח **צילום קבלה או PDF** ישירות בוואטסאפ. מושקו:
1. מוריד את הקובץ, קורא אותו, ומחלץ ספק, ח.פ, סכום, מע"מ ותאריך.
2. אם לא קריא או שהביטחון נמוך — **אומר זאת ולא יוצר הוצאה**. לא ממציא סכום.
3. בודק כפילות מול מה שכבר בספרים — כפילות ודאית עוצרת.
4. מציג לך את מה שחילץ.
5. **לתיוק בספרים** — לבקש במפורש; זו פעולת כתיבה שעוברת אישור.

תקרה יומית פר-ארגון על קליטה מהצ'אט, כדי שלא תישרף מכסה בטעות.

## שלב 9 — שאלות ובקשות (מה אפשר לבקש)

**שאלות**: "מה התזרים שלי?" · "מתי צפוי מינוס בחשבון?" · "מי לא שילם לי?" ·
"מה מצב המע"מ?" · "האם קלטת את ההוצאות של החודש?" · "מה חסר לי לדיווח?" ·
"כמה מס אני צריך לשלם?" (יגיע **תמיד** עם הסתייגות — האומדן גס) ·
"מה כדאי לשפר בעסק?" (יענה ממספרים אמיתיים, לא מעצות כלליות).

**בקשות פעולה**: "תייק את ההוצאה הזאת" · "שלח לבנק את הרווח וההפסד של יוני" ·
"תוציא חשבונית ללקוח X" · "רשום שדיברתי עם הלקוח על החוב".

**דיווח מע"מ**: "תאשר לי את הדיווח של יוני" — מושקו יריץ אימות משולש, יציג את
המספרים, וירשום את אישורך. ⚠️ **רצף אינה משדרת לרשות המסים** — השידור בפועל
נעשה בממשק SUMIT. אם האימות נכשל, מושקו **חוסם** ולא נותן לאשר.

## כיבוי חירום

- וואטסאפ: הסר את ה-Webhook ב-Meta App, או מחק את `WHATSAPP_ACCESS_TOKEN`.
- טלגרם: `POST https://api.telegram.org/bot<TOKEN>/deleteWebhook`.
- משתמש בודד: סמן `revoked_at` ב-`ChannelIdentity` שלו — זהות מבוטלת מתנהגת
  בדיוק כמו זהות שאינה קיימת.
- קליטת קבלות: `CHAT_RECEIPT_INTAKE_ENABLED=false`.
- התרעות: `push_enabled=false` על הזהות.
